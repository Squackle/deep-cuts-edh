# Weekly Dispatch — provider and subscriber safety preflight (2026-10-19)

Owner-approved feature tracked in [#66](https://github.com/Squackle/deep-cuts-edh/issues/66). **This draft does not send email, enroll subscribers or enable a schedule.**

## Implemented staging component

`src/weekly-dispatch-template.js` is a pure HTML + plain-text email renderer. It accepts *only explicitly supplied published/public content* and refuses non-site links, unsafe headlines and empty editions. Its preview mode deliberately uses a placeholder postal address and unsubscribe target; **delivery mode requires a real, signed unsubscribe URL and public mailing address**. No network, contact lookup, OAuth, D1 or mail sending is involved.

The existing Google Apps Script sender in `scripts/google-mailer/` is exclusively for 8-digit **profile verification/recovery codes** and has a 60-recipient daily cap. Do not use its secret or account recovery email table for weekly marketing.

## Required implementation before owner can enable live sending

1. Newsletter service/provider selection and domain ownership verification (SPF, DKIM and DMARC). Store credentials only as Cloudflare encrypted secrets. Separate from recovery sender.
2. Owner-approved sender display name/reply address, verified domain, real public postal address, delivery day and Central Time preference.
3. Separate double-opt-in workflow: public signup email entry, timestamped consent record, limited confirmation token expiring after a short period, per-IP abuse limits, no user enrollment from profile-recovery addresses or supporter payments.
4. One-click unsubscribe with cryptographic bearer link and immediate suppression at all queued/retried batches; include suppression on bounces and complaints. Provide deletion/export capability and privacy policy detail.
5. Owner-only preview and test-recipient confirmation in the authenticated Owner Command Center. Never send a complete production edition until owner manually approves a successful first test.
6. Independent Cloudflare Cron Worker driven by a configured recurring schedule, with zone-aware schedule evaluation, issue ID unique per Central calendar week, idempotent per-recipient delivery records, rate caps, retries, failure metrics and owner pause switch. The dashboard shows last attempted/completed send and provider errors without leaking subscriber addresses.
7. Editorial feed sources must be already published and eligible: approved Rescue Reports, selected public Community deck highlights, existing daily puzzle links, Commander Matchmaker once available, and only later vetted Hidden Tech if approved. No private collection, hidden comments, draft articles, unpublished users or autogenerated invented editorial descriptions.
8. Review data migration/backup and rollback **separately** before applying any new subscriber/edition/outbox tables to production D1; never modify existing profile, score or payment schema casually.

## Draft-only acceptance gates

- **No bulk email** before verified provider, double opt-in, unsubscribe/suppression and owner-approved sender/address.
- Check repeated Cron invocations, window overlaps, single-recipient reruns, bounce lists, time-zone changes, failed provider responses and empty weeks without sending duplicates.
- Render email compatible HTML and plain text; human-readable source URLs; tests for escaping and verified published content, no tracking-pixel requirement.
- Use only reviewed owner-auth APIs for subscriber counts and manual pause; no public admin controls.
- The drafted `src/weekly-dispatch-template.js` is NOT a scheduler, subscriber database, sender, or evidence a real email went out.
