# Field Network & Library UX Bundle — October 13, 2026

## Profile mentions and identity layout

- Every `@Username` reference in Field Network's discussion-card headlines, content and metadata links to `community.html?profile=Username`. The normal profile lookup opens the Network tab and displays the user's dossier; it is case-insensitive in the API. This covers Rescue Challenge entry labels, recent public deck authors, comments, activity feeds and match reports. The full deck page's `@author` label also links directly to the profile.
- Mention rendering uses **text nodes and real anchors**, never injected HTML. The syntax is only `@Username` where the handle begins with a letter and has 3–24 letters, numbers or underscores. Email addresses remain ordinary text. Invalid/unregistered mentions lead to a normal "Profile not found" message instead of an unsafe redirect.
- Sidebar's **YOUR IDENTITY** tile stacks the portrait above a full-width username/bio, avoiding the previous squeeze between a 96px avatar and the 252px sidebar. Username is itself a link to the profile. Long handles wrap without spilling out.

## Optional single emoji bio prefix

- Registration and Edit Dossier offer a **single, optional emoji** from a curated list of 31. The chosen emoji is saved separately from the 240-character bio and displayed before the bio text, not inside the editable bio text.
- Server-side `BIO_EMOJIS` allowlist restricts submissions. No custom HTML or arbitrary combined characters are accepted. The D1 migration adds `bio_emoji TEXT NOT NULL DEFAULT ''` to `community_profiles`; existing users' bios and identities remain unchanged.
- Added the `bio_emoji` response field for the authenticated profile and public profile read paths.

## Card Library: Scryfall-native browsing

- Retained the existing Scryfall API integration, because it already powers **Add to Deck** and the detail modal; an iframe would not reliably preserve those interactions and may be blocked by Scryfall's framing policy.
- Expanded sorts with distinct directions for EDHREC rankings, price ascending/descending, name, mana value, release date and rarity; added power, toughness, color, artist and set sorting.
- Added numeric **minimum and maximum USD price** inputs, supporting cents; both feed into the live Scryfall search as `usd>=...` / `usd<=...`. Impossible ranges and values outside $0–$100,000 are rejected before a search starts.
- Printing selector: unique cards, individual prints (so editions/prices can be compared), or distinct artworks. Pagination uses print IDs when browsing multiple printings and card Oracle IDs otherwise.
- Direct links to **Scryfall Advanced Search**, **Scryfall Tagger**, the Scryfall syntax guide, and per-card Tagger detail when set and collector number are available. The "Search on Scryfall" action synchronizes current query, sort and printing mode in its URL. External sites open in a separate tab with `noopener noreferrer`.
- The advanced filter fold still works on narrow screens; the quick name/format/type search stays visible.

## Page-specific logo taglines

The site header now uses a short, page-specific catchphrase for the Home, Card Library, Deck Workshop, Nominations, Field Network, Supporters, Field Office, and each published Rescue Report. On the Home page, moving between the `#latest` and `#archive` anchors updates the tagline dynamically. Field Network's internal Cases, Decks, Rescue Challenge, Lab, Network and Account panels also update it dynamically. The logo and navigation destinations are unchanged.

## Migration and validation

The migration `db/community-bio-emoji.sql` was applied to the production D1 *before* the new application deployment. Do not rerun the `ALTER TABLE` statement.

Before deployment, validate JS module syntax, input IDs, API registration and edit fields, mention escaping, Scryfall query URL generation and price-range validation; ensure D1 `PRAGMA foreign_key_check` is empty. Afterwards, smoke-test the live Scryfall results, individual profile links, user avatar/bio updates, navigation taglines, and mobile identity card. These are external-browser/manual checks unless explicitly reported completed; a successful Cloudflare build alone does not guarantee all browser interactions.
